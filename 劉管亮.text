1️⃣ Using MediaPipe on Android

MediaPipe supports Android natively via AAR libraries.

You don’t need to convert Python code to Java/Kotlin.

The difference from Python:

Camera input: use CameraX / SurfaceView / OpenGL

Data processing: done in Kotlin/Java

Output: send to UI or Unity



Recommendation: Use MediaPipe Android library and implement your pipeline in Kotlin/Java.


---

2️⃣ Front-end vs Back-end

Front-end: UI/UX, camera preview, results display, Unity visualization

Back-end (local): logic, data processing, MediaPipe analysis, scoring, feedback

Optional cloud back-end: only needed if using OpenAI API or shared data


Integration Example:

Camera → MediaPipe → Local API (score & feedback) → UI + Unity


---

3️⃣ Adding Unity

Unity handles 3D visualization & animation:

3D character models

Action demonstration

Scene switching

Visual effects


Unity can be embedded as a library inside Android:

Android calls Unity methods → Unity animates the character


Communication methods:

Unity as library (recommended)

Unity as separate app (via REST API)

Unity WebGL (less common for mobile)




---

4️⃣ System Integration Role

Your job: connect Android + MediaPipe + Unity + optional server/API

Required languages/tools:

Android app: Kotlin or Java

Unity: C#

Back-end / optional server: Python or Node.js

Data integration: JSON, REST API

Build/automation: Gradle (Android), Unity Build System


Workflow:

1. Prototype logic in VS Code (Python, Node.js, or Kotlin)


2. Test data flow: MediaPipe → local API → Unity


3. Move to Android Studio for final APK build





---

5️⃣ API Basics

API = Application Programming Interface

It defines how programs talk to each other

Can be local (inside the app) or online (cloud service)



Local API

Just a method/function in your app

Connects modules inside the phone

Example:


fun analyzeHandMovement(handData: HandData): Feedback {
    val score = calculateTrajectoryScore(handData)
    val message = if (score > 0.8) "Great!" else "Try again!"
    return Feedback(score, message)
}

Android UI calls this method → returns structured result → Unity animates if needed


Online API

Hosted on a server (like OpenAI, Google)

Requires an API key to access

Used for cloud processing, AI, or data sharing



---

6️⃣ Local API vs Online API

Aspect	Local API	Online API

Location	Inside device	Remote server
Key needed	No	Yes
Purpose	Connect app modules (MediaPipe → Unity → UI)	Connect to external services (OpenAI, cloud DB)


Key point: For your rehab app, local API is enough for MediaPipe + Unity integration. Online API only if using OpenAI or other cloud processing.
